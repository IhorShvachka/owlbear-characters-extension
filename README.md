# Персонажі — розширення для Owlbear Rodeo

Розширення перебудовується з інструмента для токенів на інтерактивні листи персонажів. Поточна стабільна версія в `main` — попередній інструмент для токенів. Нова робота ведеться в гілці `feature/interactive-character-sheets` і ще не опублікована.

## Нова цільова функціональність

- ГМ імпортує JSON-файл персонажа, спочатку зосереджуємося на D&D 5e.
- Нормалізатор дістає поширені поля (характеристики, рівень, КЗ, очки здоров’я, навички, спорядження, заклинання) та зберігає оригінальні дані для непідтримуваних полів.
- ГМ призначає персонажа гравцеві з кімнати.
- Гравець редагує власний лист; ГМ може редагувати будь-який лист.
- Інтерфейс листа не залежить від конкретного джерела JSON; додаткові адаптери форматів можна додавати окремо.

## Поточний стан гілки

- Аудит наявної Vite + TypeScript структури й поточного токен-орієнтованого UI.
- Документована цільова архітектура та критерії приймання: `docs/INTERACTIVE-SHEETS-ARCHITECTURE.md`.
- Додано першу версію D&D 5e JSON-нормалізатора: `src/dnd5e-import.ts`.
- Інтеграція імпорту з інтерфейсом, призначення гравцям, редагування й перевірки реальної кімнати ще попереду.

## Важливе обмеження приватності

Метадані кімнати Owlbear Rodeo є спільними для кімнати й мають ліміт менш як 16 kB загалом. Не можна використовувати їх як приватну базу повних листів. Фільтрація інтерфейсу не захищає від перегляду даних через інструменти розробника, якщо всі листи вже передані клієнту. Для справжньої ізоляції потрібне серверне сховище з авторизацією кожного читання/запису. До реалізації цього шару розширення не повинно обіцяти сувору конфіденційність чужих листів.

## Розгортання

GitHub Actions публікує `dist` у GitHub Pages лише після push до `main`. Гілка розробки не замінює поточну опубліковану версію.

## Локальна розробка

```bash
npm install
npm run dev
npm run build
```
