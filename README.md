# Персонажі — розширення для Owlbear Rodeo

Перероблення з інструмента для токенів на інтерактивні листи персонажів ведеться в гілці `feature/interactive-character-sheets` та чернетці [PR #1](https://github.com/IhorShvachka/owlbear-characters-extension/pull/1). Зміни ще не опубліковані в GitHub Pages і не змінюють `main`.

## Реалізовано в гілці

- Аудит попередньої Vite + TypeScript архітектури.
- Імпорт JSON із перевіркою синтаксису та розміру файла.
- Попередній перегляд розпізнаних полів D&D 5e перед імпортом.
- Перелік персонажів для ГМ, призначення й перепризначення гравцям, відкриття та видалення листів.
- Лист із базовими характеристиками, HP, КЗ, ініціативою, швидкістю, навичками, спорядженням, заклинаннями, рисами та оригінальним JSON.
- Редагування бойових значень і нотаток власником листа або ГМ.
- Автоматична перевірка GitHub Actions: `npm install` і `npm run build` успішно завершилися в запуску [№4](https://github.com/IhorShvachka/owlbear-characters-extension/actions/runs/40238992406).
- Збереження в метаданих кімнати лише як тимчасова основа прототипу.

## Критичне обмеження приватності

Метадані кімнати Owlbear є спільними, а клієнт розширення отримує ці дані. Приховування листів у UI не є захистом: учасник із технічними знаннями може дослідити спільні дані. У цій версії **не можна гарантувати, що гравець не зможе прочитати чужий JSON**. Також метадані мають загальний ліміт менше 16 КБ, тому вони не підходять для повних листів. Перед реальною грою потрібен зовнішній сервер зі сховищем і авторизацією кожного запиту на читання та запис. [Документація Owlbear: метадані кімнати](https://docs.owlbear.rodeo/extensions/apis/room/).

## Наступні кроки

1. Перевірити імпорт на реальних JSON-експортах D&D 5e та уточнити адаптер під конкретний формат.
2. Додати автоматизовані тести для нормалізатора JSON.
3. Спроєктувати й реалізувати захищений бекенд, який перевіряє особу гравця та права доступу на сервері; не покладатися на фільтрування в клієнті.
4. Провести перевірку у справжній кімнаті Owlbear: призначення листів, редагування ГМ і гравцем, синхронізація кількох клієнтів.
5. Лише після цього вирішувати питання злиття в `main` та публікації.

## Ручний чекліст для перевірки в Owlbear Rodeo

- [ ] ГМ відкриває розширення й бачить інструменти імпорту.
- [ ] Некоректний JSON показує помилку, не створюючи лист.
- [ ] Коректний JSON показує попередній перегляд до імпорту.
- [ ] ГМ може призначити лист гравцю, відкрити його й видалити.
- [ ] Гравець може змінювати поля власного листа.
- [ ] ГМ може редагувати будь-який лист.
- [ ] Зміни синхронізуються між двома клієнтами.
- [ ] Не вважати дані приватними, доки не підключено бекенд із серверною авторизацією.
